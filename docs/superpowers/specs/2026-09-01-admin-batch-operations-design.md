# 后台批量节点操作设计

## 范围

本次先实现后台节点列表的批量标签修改，包含“追加标签”“移除标签”“覆盖全部标签”三种模式。表格支持跨当前查询结果逐页选择的节点 ID，目录节点不会写入标签。

## 交互

- 后台节点表增加多选列，开启 `reserve-selection` 以跨页累积选中节点；清空选择同时重置表格内部保留状态。
- 提交前按共享契约上限本地校验，超过 200 个书签或 20 个标签时提示已选数量而不发起请求。
- 模式单选组用 `div` 加 `aria-labelledby` 关联标题，而不是包裹在 `label` 内：单个 `label` 不应指向含多个可聚焦控件的单选组。
- 选择节点后显示批量操作栏和已选数量。
- 批量标签按钮打开对话框，要求选择操作模式并输入标签集合。
- 追加模式保留原标签并合并输入值；移除模式删除匹配标签；覆盖模式将书签标签替换为输入值。
- 未选择书签时按钮不可提交；只选择目录时提示“没有可修改的书签”。
- 提交期间锁定操作，成功后清空选择并关闭对话框；部分跳过或失败时展示汇总信息。
- 标签写入同时改变前台树与筛选候选，因此成功后向宿主发出 `tags-updated`，由宿主重载树；树引用变化本身会触发表格刷新，仅在重载失败时递增刷新令牌补偿。

## 后端

- 新增管理员专用批量标签接口，使用共享 Zod 契约校验节点 ID、模式和标签上限。
- Repository 在单个数据库事务中锁定并读取节点，确认节点类型和存在性后批量替换关联标签。
- 标签写入按集合展开为固定四条语句（一次删除关联、一次标签 upsert、一次标签查询、一次关联插入），语句数与节点和标签规模无关，避免长事务放大往返并长时间持锁。
- 标签 upsert 使用 `ON DUPLICATE KEY UPDATE normalized_name = normalized_name` 的显式空操作，保证既有标签的展示名不被本次写入改写。
- 标签名称按现有规则 trim、大小写无关去重；空标签仅允许覆盖模式，表示清空标签。
- 接口统一返回更新数量、跳过目录数量和未找到数量；事务异常整体回滚并透传统一错误。
- 批量与查询接口都经过共享 `malformedJsonGuard`，畸形请求体返回 42201 而非 500。

## 测试

- 契约测试覆盖模式、ID 集合、标签数量和空值边界。
- Repository 测试覆盖追加、移除、覆盖、目录跳过、多节点差异、事务回滚、稳定参数顺序、语句数量上界和展示名保护。
- 路由测试覆盖管理员鉴权、CSRF 缺失与错误、契约边界、畸形 JSON、领域错误透传和完整路径注册。
- 前端测试覆盖多选状态、跨页累积、清空选择、三种模式提交、上限拦截、空标签边界、提交锁、成功后清空并通知宿主，以及失败后保留选择。
