# CanCanWorld 功能治理路线图设计

## 背景

节点创建、指定目录保存、删除反馈和删除关联数据清理已经发布。下一批需求包含六类能力：批量管理、重复与失效链接治理、高级搜索与筛选、回收站与审计、一键收藏、目录分享。

这些能力横跨后台查询、事务写入、数据生命周期、匿名访问和外部客户端认证。若一次性合并，会让数据库迁移、权限边界和回滚策略互相耦合，也难以在每次发布后确认问题来自哪一层。因此需要先确定整体依赖，再把每个阶段作为独立的规格、计划、实现和发布周期。

## 已确认范围

- 后台高级筛选、保存筛选条件和快速定位目录。
- 多选书签，批量移动、删除、修改标签、公开状态和启用状态。
- 重复 URL 检测、合并建议、失效链接复查和批量治理。
- 删除进入回收站、恢复、永久清理和管理员操作审计。
- 目录只读分享，可撤销，可配置密码和过期时间。
- 浏览器一键收藏，自动获取当前页标题和地址，并可选择目录、标签和公开状态。

## 方案比较

### 方案一：一次性完成六项后统一发布

优点是最终功能同时可用，页面只需要经历一次大调整。缺点是数据库和接口变更面过大，回归定位困难；分享与浏览器收藏的认证模型也会拖慢后台管理功能交付。不采用。

### 方案二：按依赖关系分阶段垂直交付

每阶段同时完成契约、后端、前端、测试、真实浏览器验收和发布。先建立服务端查询与数据生命周期，再做批量和治理，最后开放匿名分享与外部捕获。每个阶段都能独立使用、独立回滚，并给下一阶段提供稳定接口。采用此方案。

### 方案三：先用前端本地计算快速补齐交互

继续加载完整目录树，在浏览器内分页和筛选，并循环调用单条接口完成批量操作。短期代码少，但数据量增长后性能不稳定，跨页选择缺少服务端快照，循环写入会出现部分成功和重复刷新。不采用。

## 阶段顺序

### 第一阶段：后台高级查询与筛选

新增管理员节点查询接口，提供服务端分页、稳定排序、目录范围、标签、可见性、启用状态、检测状态和时间范围筛选。筛选条件可以保存，结果路径可以快速定位到前台目录。

这是后续批量治理的查询基础。详细规格见 [管理后台高级查询与筛选设计](./2026-09-01-admin-query-design.md)。

### 第二阶段：回收站与操作审计

节点删除改为软删除，并记录删除批次。管理员可以查看、恢复、指定目录恢复和永久清理；父目录同时删除时按批次恢复层级，父目录已永久清理时要求选择新的目标目录。

审计覆盖创建、编辑、移动、删除、恢复、永久清理、批量操作、分享和捕获令牌管理。日志只记录必要的主体、动作、目标、数量、请求 ID、结果和时间，不记录密码、Cookie、原始令牌或完整敏感请求体。

### 第三阶段：批量管理

后台表格支持跨页勾选书签，批量移动、移入回收站、添加或移除标签、设置公开状态和启用状态。首版不批量操作目录，避免目录循环、父子重复选择和大范围级联误操作。

批量写入使用专用事务接口，最多处理 200 条显式 ID。一次请求要么全部提交，要么全部回滚；成功后只刷新一次查询和目录树。后续数据规模证明有必要时，再设计“选择当前筛选的全部结果”的服务端筛选快照。

### 第四阶段：重复与失效链接治理

治理工作台复用现有 `url_hash`、链接检测任务和检测历史：

- 重复链接按规范化 URL 分组，不增加唯一约束。
- 合并前预览标题、路径、标签、备注、点击量和检测状态，由用户明确选择保留项。
- 合并后的其余书签进入回收站，操作可恢复并写入审计。
- 失效判断不能依据单次超时；默认要求最近检测仍在有效期内，并满足明确状态或连续失败次数。
- JavaScript 书签不参与 HTTP 失效判断。
- 支持重新检测、编辑、忽略和批量移入回收站。

### 第五阶段：目录分享

管理员为目录生成随机分享凭据，服务端只保存摘要。分享可撤销，可配置密码和过期时间，默认实时读取该目录下已启用且公开的节点，不允许分享绕过私有内容边界。

匿名访问只能看到授权子树，不能枚举其他目录或泄露祖先路径。密码校验需要速率限制；分享页面为只读，并覆盖桌面和移动视口。目录移动后分享继续指向同一目录 ID，目录进入回收站、分享过期或被撤销后立即失效。

### 第六阶段：浏览器一键收藏

首版采用 Chromium Manifest V3 扩展。扩展通过一次性配对获得可撤销、仅允许创建书签的捕获令牌，不复用主站 Cookie、CSRF Token 或目录分享令牌，也不放宽主站管理接口的跨域策略。

扩展自动读取当前页标题和地址，加载可选目录与标签，提交前提示重复链接，并使用幂等键防止重复点击创建多条记录。令牌只显示一次、服务端只保存摘要、日志必须脱敏。Bookmarklet 仅作为后续受限环境的降级入口。

## 全局工程约束

- 保持 Vue 3、Bun/Hono、MySQL 单体架构，不引入 Redis、消息队列、搜索服务或额外微服务。
- 现有公开搜索和单条节点接口保持兼容；新后台能力使用管理员专用接口。
- 所有写操作通过 Repository 事务执行，路由只负责鉴权、校验和响应映射。
- 所有新增代码、复杂逻辑、配置和数据库迁移使用有意义的中文注释；DDL 字段说明使用 `COMMENT`。
- 数据库迁移只向前增加，不修改已发布迁移；备份与恢复格式在新增持久数据时同步升级并保持兼容。
- 令牌按用途隔离，分享令牌、捕获令牌和登录会话不能互换。
- 每个阶段完成共享契约测试、Repository/API 测试、前端模型与组件测试、类型检查、生产构建和真实浏览器验收。
- 每个阶段单独提交并合并到 `main`，运行合并后完整门禁，推送 GitHub，并确认发布工作流与 GHCR 镜像成功。

## 总体验收标准

- 管理员无需逐条维护大量书签，筛选和批量写入不会产生部分成功。
- 删除与治理操作可恢复、可追踪，永久清理前有明确影响范围和二次确认。
- 重复和失效判断可解释，不会因一次网络抖动自动删除数据。
- 匿名分享只能读取明确授权的公开内容，撤销与过期即时生效。
- 浏览器收藏凭据权限最小化，恶意网页不能读取或复用管理员会话。
- 每次发布均有自动化验证、真实页面验收和可追溯的容器镜像摘要。
