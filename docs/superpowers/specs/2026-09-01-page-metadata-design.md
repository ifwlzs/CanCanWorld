# 书签元数据抓取设计

## 范围

新建或编辑书签时，管理员点击地址框旁的按钮，由服务端抓取目标页面并回填网站名称和注释。本阶段只做后台编辑器入口；浏览器扩展复用同一抓取服务，作为后续阶段交付。

## 交互

- 地址框旁增加「获取信息」按钮，仅书签类型可见，地址为空时禁用。
- 点击后按钮进入加载态并锁定重复点击，成功后按覆盖策略写入表单。
- 名称或注释为空时直接填入；两者都已有内容时弹确认框询问是否覆盖，取消则保留原值。
- 抓取失败展示服务端原因，表单内容一律不变，用户可修正地址后重试。
- 抓取只影响表单草稿，不写数据库；用户仍需点保存才落库。

## 后端

- 新增管理员专用接口 `POST /api/v1/admin/page-metadata`，输入单个 URL，返回 `title`、`description` 和最终地址。
- 抓取服务 `PageMetadataFetcher` 复用现有 `UrlPolicy`：拒绝非 HTTP 协议、内嵌凭据、非放行端口和所有非公网地址，逐跳重定向都重新校验，并通过 pinned lookup 固定到已验证地址，不新开网络出口。
- 复用链接检测的超时、重定向上限和端口白名单配置，新增独立的响应体上限，避免大页面拖垮抓取。
- 只接受 HTML 类响应；超过上限即截断，因为 `<head>` 位于文档开头，截断不影响元数据提取。
- 用已有的 `parse5` 解析 DOM，不新增依赖。标题优先级 `og:title` → `twitter:title` → `<title>`；描述优先级 `og:description` → `twitter:description` → `<meta name="description">`。
- 编码按 `Content-Type` 的 charset 与 HTML `<meta charset>` 判定，GBK 等非 UTF-8 页面用 `TextDecoder` 转码，避免中文站点乱码。
- 输出按契约上限截断（名称 512、注释 10000），与 `createNodeSchema` 保持一致，并折叠连续空白。
- 抓取失败透传统一 AppError envelope；日志不记录响应体，避免把远端页面内容写进日志。

## 安全

- 接口要求管理员登录并校验 CSRF，与其他写接口一致。
- 远端页面内容属于不可信输入：只提取文本并按纯文本回填，不渲染 HTML，不执行脚本。
- 抓取是由用户输入地址驱动的对外请求，`UrlPolicy` 是唯一出口守卫，禁止绕过。

## 测试

- 抓取服务测试覆盖三级标题与描述优先级、HTML 实体解码、非 UTF-8 转码、缺失元数据、空白折叠、超长截断、非 HTML 响应拒绝、响应体上限截断和重定向后地址。
- 地址策略测试确认内网地址、非法协议、内嵌凭据和非放行端口在发出请求前被拒绝。
- 路由测试覆盖管理员鉴权、CSRF 缺失与错误、契约边界、畸形 JSON 和领域错误透传。
- 前端测试覆盖按钮禁用条件、加载锁、空字段直填、非空字段确认覆盖与取消保留、失败后表单不变。
