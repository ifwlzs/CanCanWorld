# 节点创建与删除可靠性设计

## 背景

当前前台和管理后台复用 `NodeEditor` 创建目录或书签。后端创建接口已经支持通过 `parentId` 指定任意父目录，但前端保存逻辑会用前台当前目录覆盖弹窗提交值，管理后台也没有显式的目标目录控件。

新建请求失败时，页面没有提交状态、字段级校验或错误展示。服务端拒绝请求后弹窗保持原状，用户只能看到“点击保存没反应”。在当前数据库中以“软件更新”为名称执行等价目录插入可以成功，因此该名称和数据库目录模型不是失败原因，问题集中在浏览器到接口的提交链路及其不可见错误。

删除书签的现有实现会清理标签、检测历史、检测任务项目、图标任务项目和图标缓存，但没有覆盖该路径的自动化测试。真实数据库回滚验证表明，一条关联 27 个检测任务和 3 个图标任务的书签可以正确删除，但逐任务重算总数会产生大量串行数据库往返，完整事务约需 17 秒，存在反向代理超时、锁等待和并发失败风险。

## 目标

- 前台可以在当前目录中新建目录或书签，也可以在弹窗中改选任意目标目录。
- 管理后台可以明确选择任意层级目标目录，默认保存到根目录。
- 用户始终能看到字段错误、提交进度、服务端错误和成功结果。
- 删除书签能够可靠清理全部关联数据，并批量重算受影响任务总数。
- 自动化测试覆盖创建表单的数据流和书签删除事务。

## 非目标

- 本次不重新设计管理后台导航或增加常驻目录侧栏。
- 本次不在编辑弹窗中提供节点移动；现有拖拽移动行为保持不变。
- 本次不修改节点数据模型、HTTP 路径或数据库表结构。
- 本次不增加新的表单验证依赖。

## 方案选择

采用共享新建弹窗内的目录树选择器。相较于后台目录侧栏，该方案改动范围更小，前后台行为一致；相较于目录行内的“在此新建”菜单，它能直接选择根目录和任意深层目录，也不会挤占移动端表格操作区。

## 前端设计

### 新建上下文

`App.vue` 打开编辑器时同时记录节点类型、编辑节点和默认父目录：

- 前台新建默认使用 `navigation.selectedFolderId`。
- 管理后台新建默认使用根目录 ID `1`。
- 编辑现有节点继续使用节点原有信息，不提供父目录修改控件。

管理后台仍只发出新建类型事件，`App.vue` 作为前后台切换和编辑器状态的所有者，负责应用后台的根目录默认值。这样 `AdminPanel` 不直接操作导航 Store，也不复制创建逻辑。

### 目录选择器

`NodeEditor` 接收完整导航树和默认父目录 ID，并把树转换为只包含目录的选择数据。选择数据包含一个代表系统根的“全部书签”节点，目录按现有树顺序递归挂载，书签不进入候选项。

仅在新建模式显示“保存到”字段，使用 Element Plus 树选择器并启用：

- 按目录名称过滤；
- 父子节点独立选择；
- 任意层级展开；
- 清晰的字段标签和键盘焦点；
- 窄屏下占满表单宽度，不产生横向滚动。

### 表单校验与提交状态

沿用 Element Plus 表单能力，不引入 VeeValidate 或 FormKit。规则只覆盖当前业务契约：

- 名称去除首尾空白后不能为空；
- 书签地址去除首尾空白后不能为空；
- 目标目录必须是有效正整数。

表单验证通过后才发出提交事件。`App.vue` 维护异步保存状态和服务端错误：

- 保存期间按钮显示加载状态，禁止重复提交并阻止关闭弹窗；
- 新建请求直接使用表单中的 `parentId`，不再覆盖为前台当前目录；
- 请求失败时保留弹窗、输入值和目录选择，在弹窗内显示可感知的错误提示；
- 请求成功后关闭弹窗、重载目录树并显示成功消息。

字段错误显示在对应输入旁。服务端或网络错误使用弹窗内警告区域，并通过语义化警告组件让辅助技术能够感知；全局消息作为补充，不作为唯一错误载体。

## 删除设计

### Repository 事务

删除节点仍在单一事务中完成，维持以下顺序：

1. 锁定并验证目标节点。
2. 对非空目录执行现有显式删除策略。
3. 收集受影响的检测任务和图标任务 ID。
4. 删除标签关联、检测历史、任务项目和图标缓存。
5. 分别用一条批量更新语句重算所有受影响检测任务和图标任务的 `total`。
6. 清理孤立标签并删除节点。
7. 提交事务；任何步骤失败均回滚。

批量更新使用受影响任务 ID 限定范围，并通过相关子查询计算剩余项目数量，避免逐任务数据库往返，也不扫描或修改无关任务。

### 页面反馈

普通书签和空目录删除成功后显示成功消息。非空目录继续执行二次确认；级联删除失败也必须进入统一错误处理，不能产生未处理的 Promise。错误发生时目录树保持现有状态，用户可重试或刷新。

## 测试设计

### 前端

优先测试可独立提取的目录选项转换和新建上下文逻辑，并通过类型检查和浏览器场景覆盖组件集成：

- 目录选项包含根目录和所有深层目录，不包含书签；
- 前台新建默认选择当前目录；
- 后台新建默认选择根目录；
- 用户改选目录后提交值不被覆盖；
- 空名称和空书签地址不会发送请求；
- 提交中禁止重复保存；
- 服务端失败时弹窗和输入保留并展示错误；
- 成功后弹窗关闭、树刷新并展示成功消息。

### 后端

为 `NodeRepository.delete` 增加基于真实事务调用顺序的单元测试：

- 无关联书签可以删除并提交；
- 有标签、检测日志、检测任务、图标任务和图标缓存的书签按顺序清理；
- 多个受影响任务分别只执行一次批量总数更新；
- 任一步骤失败时回滚且不提交；
- 非空目录无策略时仍返回 `40904`，既有行为不回归。

### 综合验证

- 运行全部后端测试、前后端类型检查和生产构建。
- 在桌面和移动视口检查弹窗布局、目录搜索、加载状态和错误提示。
- 通过实际 API 创建并删除临时目录和书签，验证刷新结果；测试数据在验证结束后清理。
- 对有关联记录的现有书签使用回滚事务验证优化后的删除 SQL，不改动用户数据。

## 验收标准

- 前台当前目录和管理后台任意指定目录均能成功创建名为“软件更新”的目录。
- 新建目录或书签发生校验、认证、网络或服务端错误时，用户能看到明确原因，不再表现为“没反应”。
- 连续点击保存只产生一个创建请求。
- 删除有关联数据的书签不会遗留标签、检测记录、任务项目或图标缓存。
- 删除事务对检测任务和图标任务各最多执行一条总数批量更新语句。
- 全部自动化验证通过，桌面和移动端不存在弹窗内容重叠或横向滚动。
