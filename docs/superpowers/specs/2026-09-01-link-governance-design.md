# 重复与失效链接治理设计

## 范围

后台新增治理工作台，包含重复 URL 分组和失效书签两个视图。重复组由用户选定保留项后删除其余书签；失效书签支持重新检测、编辑和批量清理。本阶段复用现有 `url_hash`、检测任务和检测历史，不新增数据表。

## 真实数据基础

生产库当前 6279 个书签、6127 条已检测、16 万条检测历史，平均每书签 26.6 条记录。重复组 223 组涉及 533 个书签。

连续失败分桶为 1 次 195 个、2 次 69 个、3-4 次 83 个、5-9 次 91 个、10-29 次 1301 个、30 次以上 3 个，其中 1231 个书签从未成功过，多为导入的历史失效链接。按默认阈值实测命中 1200 个。

阈值从 2 调到 5 只把命中数从 1261 降到 1137，说明绝大多数命中项的失败次数远高于阈值，阈值主要用于挡掉 1 到 2 次的网络抖动（合计 264 个），而不是用于粗筛。

## 重复检测

- 按 `url_hash` 分组，只统计 `node_type = 'bookmark'` 且 `url_hash` 非空的节点，不新增唯一约束。
- JavaScript 书签同样参与重复分组，因为逐字相同的脚本书签确实是重复项。
- 每组返回全部成员的标题、完整路径、标签、备注、点击量、可见性、创建时间和最近检测状态，供用户判断保留哪一条。
- 分组按成员数量倒序、`url_hash` 升序，保证分页稳定。
- 合并由用户显式指定保留 ID 和待删除 ID 集合：服务端校验两者同属一组、保留 ID 在组内、待删除 ID 不含保留 ID，然后在单事务内删除其余书签并清理关联数据。
- 本阶段删除为物理删除，复用 `deleteNodeRelations` 清理标签、检测历史、任务项和图标。回收站阶段上线后改为移入回收站。

## 失效判定

失效不能依据单次超时。书签被判为失效需满足以下任一条件，且最近检测时间在有效期内：

- 最近一次状态属于确定性失败：`NOT_FOUND`、`DNS_ERROR`、`SSL_ERROR`。
- 最近一次成功之后的连续失败次数达到 3 次，成功状态指 `UP` 与 `REDIRECT`。

不参与失效判定的情况：

- JavaScript 书签不发起 HTTP 请求，一律排除。
- 从未检测过的书签排除，缺少数据不等于失效。
- `UNAUTHORIZED` 与 `FORBIDDEN` 排除：需要登录或拒绝爬虫的站点仍然可用。
- 最近检测时间超过有效期的书签排除，过期数据不足以支撑判断，提示用户先重新检测。

失效列表返回连续失败次数、最近状态、HTTP 状态码、最近检测时间和判定原因，使结论可解释。

查询先用节点表字段筛出候选书签，再只为候选集聚合检测历史，避免每次查询都扫描全部 16 万行。实测默认阈值下 355 到 742 毫秒返回，与未优化版本结果完全一致。

## 交互

- 后台增加治理页，分重复与失效两个视图，均为服务端分页。
- 重复组展开显示全部成员，单选保留项，其余默认勾选待删除，可逐条取消。
- 合并前展示影响范围与二次确认；提交期间锁定操作，成功后刷新当前视图并重载前台树。
- 失效列表展示判定原因，支持单条重新检测、跳转编辑和批量清理，批量清理复用现有 200 条上限。
- 空视图给出明确说明，例如「没有重复链接」或「没有满足条件的失效书签」。

## 后端

- 新增管理员专用接口：重复分组查询、重复合并、失效查询、失效批量清理。
- 查询使用 SQL 聚合与窗口函数在数据库内完成分组和连续失败计数，不把 16 万条历史加载进内存。
- 写操作通过 Repository 单事务执行，要么全部提交要么全部回滚。
- 所有接口要求管理员登录、校验 CSRF 并经过 `malformedJsonGuard`。

## 测试

- 契约测试覆盖分页边界、保留与删除 ID 集合约束、上限。
- Repository 测试覆盖分组 SQL 形状、合并校验失败、事务回滚、失效判定各分支与排除条件。
- 路由测试覆盖鉴权、CSRF、契约边界、畸形 JSON 和领域错误透传。
- 前端测试覆盖两个视图渲染、保留项单选、合并确认与取消、批量清理上限、失败保留状态。
- 用生产库快照验证分组数量与失效数量符合预期区间。
