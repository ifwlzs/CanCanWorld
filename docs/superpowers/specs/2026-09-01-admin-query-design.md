# 管理后台高级查询与筛选设计

## 背景

管理后台“书签与目录”目前复用前台已经加载的完整目录树，在 `AdminPanel.vue` 中递归压平后执行关键词、类型筛选和数组切片分页。数据量较小时可用，但它有三个限制：分页不是服务端稳定结果、筛选条件无法跨浏览器保存、后续跨页批量操作无法建立可靠的结果边界。

现有后端 `/api/v1/search` 面向公开搜索，要求关键词且有结果上限，不适合承担管理员组合筛选。现有 `NodeRepository.search()` 已具备递归目录范围、标签关联和完整路径的基础，可以复用查询思路，但管理员列表需要独立契约和分页总数。

## 目标

- 后台节点列表使用管理员专用的服务端分页查询，不再把完整树压平后作为表格数据源。
- 支持关键词、目录范围、节点类型、可见性、启用状态、标签、检测结论、创建时间和检测时间组合筛选。
- 支持稳定排序，翻页或刷新后筛选条件和页码行为可预测。
- 管理员可以保存、应用、重命名和删除常用筛选条件。
- 结果显示完整目录路径，并能从结果快速回到前台对应目录。
- 现有前台目录树、公开搜索和节点写接口行为保持不变。

## 非目标

- 本阶段不增加批量写入、软删除、审计日志或重复链接合并。
- 本阶段不引入全文搜索引擎、Redis、游标分页或 MySQL 中文全文分词配置。
- 本阶段不改变匿名用户可见性规则。
- 本阶段不为多个管理员分别保存筛选条件；当前产品仍是单管理员模式。

## 方案选择

采用“管理员专用查询接口 + 服务端 offset 分页 + 数据库保存筛选预设”。

相较于继续在前端筛选完整树，该方案能为后续跨页批量操作提供稳定的查询契约；相较于立即使用游标分页，offset 分页与现有 Element Plus 页码控件兼容，数据规模和并发写入频率也尚未证明需要游标。筛选预设写入现有 `app_setting`，无需为单管理员模式新建专用表，同时必须通过共享 Schema 校验，不能直接信任存储的 JSON。

## 共享契约

在 `packages/contracts` 增加管理员节点查询和筛选预设契约。所有日期使用 ISO 8601 字符串，服务端统一转换和校验。

查询请求包含：

- `keyword`：可选，去除首尾空白后最多 200 字符。
- `folderId`：目录范围起点，默认根目录 ID `1`；范围只返回该目录内的节点，不返回范围起点本身。
- `includeDescendants`：是否包含全部后代目录，默认 `true`。
- `nodeTypes`：`folder`、`bookmark` 的非空集合，默认两者。
- `visibility`：可选的 `public` 或 `private`。
- `enabled`：可选布尔值。
- `tags`：最多 20 个标签，去重后参与查询。
- `tagMode`：`any` 或 `all`，默认 `any`；设置标签后目录不会匹配。
- `health`：`unchecked`、`responded`、`unreachable` 的可选集合；仅书签匹配。
- `createdFrom`、`createdTo`：可选创建时间闭区间。
- `checkedFrom`、`checkedTo`：可选最近检测时间闭区间；仅书签匹配。
- `sortBy`：`tree`、`title`、`createdAt`、`clickCount`、`lastCheckedAt`，默认 `tree`。
- `sortDirection`：`asc` 或 `desc`；树顺序默认升序，其余排序默认降序。
- `page`：从 `1` 开始，默认 `1`。
- `pageSize`：`20`、`50`、`100` 或 `200`，默认 `50`。

检测结论沿用当前产品语义：从未检测为 `unchecked`；获得任意 HTTP 状态码为 `responded`；已经检测但没有 HTTP 状态码为 `unreachable`。更细的状态码和错误类型留给第四阶段治理工作台。

响应包含：

- `items`：`NavigationNode[]`，每项包含不含节点自身的祖先目录名称数组 `fullPath`，不返回递归 `children`；界面用 `fullPath + title` 显示完整路径。
- `total`：当前筛选条件的完整结果数。
- `page`、`pageSize`：服务端确认后的分页参数。

## API 设计

### 查询节点

新增 `POST /api/v1/admin/nodes/query`，必须通过管理员会话和 CSRF 校验。使用 POST 是因为标签、状态和类型都是数组，复杂条件放入查询字符串会产生不稳定的序列化和长度限制。该接口是只读操作，但仍按管理员敏感查询处理，不允许匿名访问。

路由只执行共享 Schema 校验并调用独立的 `AdminNodeRepository`。Repository 返回结果和总数，路由使用现有统一响应结构。

### 筛选预设

新增：

- `GET /api/v1/settings/admin-node-filters`：读取已保存预设。
- `PUT /api/v1/settings/admin-node-filters`：整体替换预设集合。

预设最多 20 个。每个预设包含稳定 UUID、1 到 40 字符的名称、查询条件和更新时间；不保存 `page`，应用预设时总是回到第一页。`pageSize` 和排序可以保存，临时关键词也可以保存。名称允许重复但界面会提示，避免服务端因改名产生额外冲突语义。

新增预设时由浏览器使用 `crypto.randomUUID()` 生成 ID；`PUT` 请求提交 ID、名称和查询条件，服务端校验后统一写入当前更新时间并返回规范化集合。当前单管理员模式采用整集合覆盖，多浏览器或多标签页同时保存时最后一次成功写入生效，界面在保存成功后以服务端响应替换本地列表。

设置使用 `app_setting.setting_key = 'admin_node_filters'` 保存。读取时先解析 JSON，再用共享 Schema 校验；不存在或损坏时返回空数组并记录不含原始配置内容的警告。写入使用参数化 upsert。

## 查询与数据流

1. `AdminPanel` 打开节点页时使用默认条件请求第一页。
2. 普通输入先更新本地草稿；关键词停止输入 300 毫秒后查询，选择类筛选立即查询。
3. 每次筛选条件变化将页码重置为 `1`；翻页只改变页码。
4. 新请求开始时取消上一请求，或者用递增请求序号丢弃过期响应，避免慢响应覆盖新条件。
5. 表格保留上一页数据并显示加载状态，不因刷新清空高度或产生布局跳动。
6. 请求成功后原子替换 `items` 和 `total`；失败时保留当前结果并显示明确错误。
7. 节点创建、编辑、移动或删除成功后，重新执行当前查询；写入已成功但查询刷新失败时沿用现有“两阶段失败”语义，不允许重复执行写操作。

## Repository 设计

查询使用参数化 SQL，并将筛选条件构造成受控 SQL 片段，字段名和排序方向只能来自白名单，不能由请求文本直接拼接。

- 目录范围通过 MySQL 8 递归 CTE 获取目标目录及后代 ID；范围起点和系统根节点不作为结果返回，`includeDescendants=false` 时只匹配直属子节点。
- 关键词匹配名称、URL、备注、描述、标签和目录路径。
- 标签筛选使用 `EXISTS` 子查询；`all` 模式通过去重标签计数匹配，避免主查询 `LEFT JOIN` 后依赖 `DISTINCT` 修正重复行。
- `tree` 排序在递归 CTE 中构建只用于排序的层级键，按每级 `sort_key` 和节点 ID 形成稳定顺序。
- 其他排序始终追加节点 ID 作为稳定的二级排序，空检测时间明确排在末尾。
- 总数查询复用同一筛选条件，但只执行 `COUNT(*)`，不加载标签和路径展示数据。
- 结果路径只为当前页节点向上解析，不在每页查询中加载全部目录记录。
- 所有查询仍在 Repository 边界强制可见性；管理员接口虽要求登录，也不能依赖前端隐藏私有数据。

首版使用现有索引并在真实数据副本上执行 `EXPLAIN`。只有执行计划证明有收益时，才新增带中文 `COMMENT` 的向前迁移；不为 `%keyword%` 盲目增加普通 B-tree 或引入部署依赖较强的中文 FULLTEXT 配置。

## 前端设计

### 查询工具栏

保留现有关键词输入和节点类型分段控件，在同一工具栏增加带筛选图标的按钮。按钮显示当前生效的高级筛选数量；高级条件放入右侧抽屉，避免把管理表格上方堆满输入框。

抽屉使用符合字段语义的控件：

- 可搜索目录树选择器用于目录范围，并提供“包含子目录”开关。
- 标签使用多选菜单，提供“任一匹配/全部匹配”分段控件。
- 可见性、启用状态和检测结论使用紧凑选择控件。
- 创建时间和检测时间使用日期范围选择器。
- 排序字段和方向使用选择菜单。
- 底部提供“应用”和“重置”命令；重置恢复默认查询，不影响已保存预设。

### 已保存筛选

工具栏提供预设菜单，支持应用、另存、重命名和删除。保存和删除期间禁用重复提交；服务端失败时保留当前条件和预设列表。应用预设后关闭抽屉、回到第一页并立即查询。

### 快速定位目录

路径列显示完整路径并允许点击“定位目录”图标。书签定位到其父目录，目录定位到该目录本身。`AdminPanel` 只发出目标目录 ID，`App.vue` 关闭后台并调用现有导航 Store 选择目录，保持组件职责边界。

### 响应式布局

桌面端保持当前密集表格。窄屏下工具栏换行，搜索框占满可用宽度，高级筛选抽屉占满视口宽度；表格维持横向滚动而不压缩操作图标。加载文案、筛选计数和长预设名称不能改变工具栏高度。

## 错误处理

- 无效目录返回 `404`，不静默回退到根目录。
- 开始时间晚于结束时间、空节点类型集合或非法排序返回 `422`。
- 未登录或会话过期沿用现有认证处理，不能返回部分私有数据。
- 查询超时或网络错误保留旧结果，显示“筛选结果刷新失败”，允许只重试查询。
- 预设 JSON 损坏时服务端返回空集合并记录警告；不把损坏内容或敏感查询值写入日志。
- 过期响应不得覆盖较新的筛选结果。

## 测试设计

### 共享契约

- 默认值、长度和数组上限。
- 日期区间、空节点类型和非法排序校验。
- 预设数量、名称和查询条件校验。

### 后端

- 管理员鉴权和统一错误响应。
- 关键词覆盖名称、URL、备注、描述、标签和路径。
- 直属目录与包含全部后代目录的边界。
- 标签 `any`、`all` 与其他条件组合。
- 可见性、启用状态、检测结论和时间区间。
- 目录与书签混合分页、总数和稳定二级排序。
- 结果只加载当前页路径，`fullPath` 正确。
- SQL 参数化，非法排序值无法进入 SQL。
- 预设读取、upsert、损坏数据回退和数量上限。

### 前端

- 查询参数映射、筛选数量和重置行为。
- 条件变化回到第一页，翻页保留条件。
- 慢旧响应不会覆盖新响应。
- 加载和失败时表格布局及旧结果保持稳定。
- 预设的保存、应用、重命名、删除及失败状态。
- 定位书签父目录与定位目录本身。
- 桌面、平板和移动视口下无控件重叠或不可达操作。

### 综合验证

- 运行 `bun run check`，确认共享契约、前后端测试、类型检查和生产构建全部通过。
- 在真实 MySQL 数据副本上对默认查询、目录范围、标签组合和关键词查询执行 `EXPLAIN`，记录是否需要新增索引。
- 使用真实浏览器验证筛选、刷新、翻页、保存预设、会话过期和快速定位。
- 分别验证桌面、平板和移动视口，确认抽屉、长目录名、长预设名和加载状态不产生重叠。

## 验收标准

- 管理后台节点表格只加载当前页数据，结果总数和完整路径准确。
- 任意两种以上筛选条件组合后，翻页、刷新和重新进入后台均得到可预测结果。
- 已保存筛选在同一部署的其他浏览器登录后仍可使用。
- 快速定位能关闭后台并进入正确的前台目录。
- 查询和预设错误有明确反馈，不会清空当前结果或保存无效配置。
- 现有前台目录树、匿名搜索、节点创建编辑删除和发布流程没有回归。
